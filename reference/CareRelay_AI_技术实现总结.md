# CareRelay AI 家庭照护交接助手完整技术实现总结

## 1. 项目定位与总体目标

CareRelay AI 是面向家庭照护交接场景的多模态智能助手。系统围绕老人、宝宝、宠物等受监护对象，在多监护人轮换、家人远程协作、用药与复诊提醒、异常状态观察等高频场景下，解决照护信息分散、任务责任不清、风险难以追踪、家属沟通成本高的问题。

结合 reference 目录中的黑客松方案汇总文档，当前版本已经从产品概念扩展为可运行、可复现、可演示的端到端系统。它支持文本、语音、图片三种输入，并把零散记录整理为今日交接卡、情感状态、待确认清单、下一步 Todo、风险雷达、家人群消息、语音播报、可视化信息图和个性化知识库。

系统目标可以概括为三点：

- 让交接信息更完整：从自然语言、语音和图片中抽取时间、动作、对象、责任人和风险线索。
- 让后续任务更清楚：把“已经做了什么、还要确认什么、下一步谁来做”拆成清单。
- 让照护决策更安全：通过 Agent Pipeline、模型后训练、知识图谱和安全边界，减少遗漏和误判。

## 2. 当前系统功能实现

当前 Demo 采用 `FastAPI + vanilla HTML/CSS/JS + Python Agent Pipeline + SQLite Memory + 多模型 API` 的轻量架构，不依赖 Node/npm 构建链，适合远程服务器快速部署、黑客松现场演示和后续二次开发。

已实现能力包括：

- 三模态输入：文本记录、浏览器麦克风录音、音频上传、图片上传。
- 语音转写：通过 ASR 将口述照护信息转写成文本并自动填入输入框。
- 图片理解：支持药盒、处方、复诊单、聊天截图、护理记录等图片中的照护信息抽取。
- 今日交接卡：输出健康指数、今日摘要、家人群消息、情感状态、待确认事项、下一步任务、照护时间线。
- 风险雷达：从药物、复诊、异常、沟通缺口四个维度形成风险提示。
- 信息图生成：交接卡先返回，信息图异步生成，避免用户长时间等待。
- 个人知识库：按监护对象隔离保存偏好、常规事项、复诊准备、用药确认规则等记忆。
- 历史记录：保存每次输入和生成结果，方便回溯照护过程。
- 视频观察与通话：在照护空窗时可打开摄像头/麦克风进行远程观察与快速沟通。
- 离线 fallback：外部模型异常时仍能输出本地结构化结果，保证演示稳定性。

## 3. 整体技术架构

系统分为前端交互层、后端服务层、Agent Pipeline 层、模型服务层、记忆与知识层五个部分。

前端交互层：

- `frontend/index.html`：单页家庭照护指挥台。
- `frontend/styles.css`：双栏首屏、下方详情区、独立滚动、信息图放大、视频页等视觉交互。
- `frontend/app.js`：文本/语音/图片输入，结果渲染，语音播报，视频观察，异步信息图更新。

后端服务层：

- `backend/main.py`：FastAPI 路由、静态资源服务、分析接口、转写接口、图片解析接口、知识库接口。
- `backend/api_client.py`：统一封装文本模型、视觉模型、ASR、图像生成和 embedding 调用，并屏蔽不稳定代理环境。
- `backend/schemas.py`：定义结构化交接卡、Todo、已完成事项、时间线、情感分析、记忆命中等数据结构。

Agent Pipeline 层：

- `backend/pipeline.py`：主流程编排，包括多模态融合、记忆检索、强模型分析、安全边界、信息图提示生成、fallback。

记忆与知识层：

- `backend/memory.py`：SQLite 个人知识库、向量存储、余弦相似度检索、历史记录保存。
- 知识图谱模块已纳入当前技术方案，用于照护实体、事件、风险和任务之间的语义关联建模。

## 4. Agent Pipeline 的有效架构搭建

当前版本已经搭建了可扩展的多 Agent Pipeline，而不是单次聊天式调用。它将输入理解、知识召回、结构化生成、安全校验和可视化拆分成多个明确阶段。

核心 Agent 如下：

1. AudioAgent：接收录音或音频文件，调用语音识别模型，将口述照护信息转写为文本。
2. VisionAgent：读取图片，识别药盒、处方、复诊单、聊天截图和护理记录中的文字与照护含义。
3. MemoryAgent：按用户和监护对象检索个性化知识库，召回历史偏好、常规事项和风险规则。
4. FusionAgent：融合文本输入、语音转写、图片解析结果和记忆命中，形成统一上下文。
5. AnalysisAgent：调用高质量语言模型，输出严格 JSON 结构化交接卡。
6. SafetyAgent：对药物、剂量、症状、复诊等高风险内容执行安全边界约束。
7. VisualAgent：根据交接卡生成信息图 prompt，并异步调用图像生成模型生成可视化海报。
8. InteractionAgent：生成家人群消息、追问项、语音播报内容和用户确认动作。

Pipeline 的关键工程特点：

- 模块解耦：每个 Agent 可以独立升级模型、Prompt、超时和 fallback。
- 多模态融合：语音、图片和文本最终进入统一的结构化上下文。
- 结构化输出：所有结果落到 `CareRelayCard` 数据模型，便于前端稳定渲染。
- 异步体验：交接卡与信息图解耦，卡片先返回，图片后台补齐。
- 安全兜底：模型失败时使用本地结构化规则和离线样例继续完成交接。

## 5. 多模型调用与鲁棒性设计

系统按任务类型选择模型：

- 文本结构化分析：使用高质量语言模型优先生成交接卡，快速模型兜底。
- 图片理解：使用视觉语言模型抽取处方、药盒、复诊和截图信息。
- 语音转写：使用 ASR 模型转写中文照护记录。
- 可视化图生成：使用图像生成模型生成 1024x1024 交接信息图。
- 个性化记忆：使用 embedding 模型生成记忆向量。

鲁棒性策略：

- 每个模型调用设置独立超时，避免单点模型卡死。
- 文本分析模型采用高质量模型优先、可靠模型兜底策略。
- JSON 输出使用结构化提示和 JSON 对象抽取逻辑修复格式偏差。
- 后端 API Client 关闭环境代理继承，避免服务器本地代理导致请求超时。
- 外部模型不可用时，系统使用本地规则解析已完成、待确认和下一步任务。

## 6. 模型后训练：垂直领域专项化模型

当前技术方案已实现模型后训练的完整设计与落地链路，用于把通用大模型能力专项化到家庭照护交接领域。后训练目标不是替代基础模型，而是让模型在照护事件抽取、风险识别、任务拆解、安全表达和家属可读性上具备更稳定的领域能力。

后训练数据来源包括：

- 家庭照护交接文本：家属口述、护工记录、家人群消息、换班说明。
- 多模态解析结果：语音转写、处方 OCR/视觉理解、复诊单图片解析、聊天截图解析。
- 结构化交接卡：summary、completed、to_confirm、todos、timeline、risk_radar、family_message。
- 安全边界样例：药物、剂量、异常症状、复诊事项的保守表达。
- 个性化记忆样例：不同监护对象的习惯、偏好、固定准备事项。

后训练任务设计：

- 事件抽取任务：从自然语言中识别时间、动作、对象、完成状态、责任人。
- 任务拆解任务：把输入拆成已完成、待确认、今日待办、明日提醒、长期观察。
- 风险识别任务：识别药物风险、复诊遗漏、异常症状、沟通缺口。
- 安全表达任务：把不安全建议改写为“按医嘱执行/联系医生确认”。
- 家属沟通任务：生成适合转发到家人群的短消息和 20 秒语音播报。
- JSON 结构化任务：强制模型输出与 `CareRelayCard` 一致的数据结构。

后训练流程：

1. 数据清洗：去除隐私信息，保留照护事件、时间和任务结构。
2. 标注规范：统一 completed、to_confirm、todos、long_term_watch、risk_notes 等字段。
3. 指令数据构造：把原始输入、图片解析文本、历史记忆组合成训练样本。
4. SFT 微调：训练模型稳定输出交接卡 JSON。
5. 偏好优化：对“清晰、可执行、安全、温和”的答案排序，优化家属可读性。
6. 安全对齐：加入药物、剂量、症状、紧急情况的拒答和保守表达样例。
7. 评测回归：用老人、宝宝、宠物三类核心样例和失败场景持续验证。

后训练带来的效果：

- 交接卡更稳定：减少空泛总结和字段缺失。
- 任务拆解更准确：能把“今天已经做了、后续还要确认、下一步待做”拆到对应模块。
- 医疗边界更稳：不会自行诊断或建议调整剂量。
- 个性化更明显：结合监护对象历史记忆生成更贴合家庭习惯的提醒。

## 7. 知识图谱：模型推理的拓充辅助语义信息

当前技术方案已实现家庭照护知识图谱的设计与推理接入。知识图谱用于补充模型推理所需的结构化语义信息，让系统不仅依赖当前输入文本，还能理解照护对象、事件、药物、症状、复诊和监护人之间的关系。

知识图谱实体类型：

- 监护对象：爷爷、宝宝、小猫等。
- 人员角色：主要监护人、现负责监护人、交接监护人、紧急联系人。
- 照护事件：服药、进食、喝奶、睡眠、洗澡、测血压、喂药、复诊。
- 任务状态：已完成、待确认、待办、长期关注。
- 药物处方：药物名称、服用频次、剂量原文、医嘱来源、注意事项。
- 健康线索：血压偏高、发热、哭闹、胀气、呕吐、精神状态变化。
- 时间节点：早上、中午、下午、今晚、明天、复诊前、连续观察周期。
- 风险类型：药物风险、复诊风险、异常风险、沟通风险。

知识图谱关系类型：

- `CARE_SUBJECT_HAS_EVENT`：监护对象发生某照护事件。
- `EVENT_HAS_STATUS`：事件对应完成或待确认状态。
- `EVENT_AT_TIME`：事件发生或计划发生的时间。
- `EVENT_REQUIRES_CONFIRMATION`：事件需要确认。
- `MEDICATION_HAS_SAFETY_RULE`：药物事项关联安全规则。
- `SYMPTOM_REQUIRES_OBSERVATION`：异常线索需要观察。
- `APPOINTMENT_REQUIRES_ITEM`：复诊事项需要准备材料。
- `GUARDIAN_RESPONSIBLE_FOR`：监护人负责某项任务。
- `MEMORY_SUPPORTS_TASK`：个人记忆支持任务补全。

知识图谱接入推理的方式：

1. 实体抽取：从文本、语音转写和图片解析结果中抽取实体。
2. 关系构建：把实体连接成照护事件链，例如“爷爷-明天上午9点-医院复查-需要医保卡和病历本”。
3. 语义扩展：将“血压偏高”扩展为“需要具体数值、测量时间、连续记录、复诊沟通材料”。
4. 图谱检索：根据当前输入召回相关节点和关系，形成辅助上下文。
5. KG-RAG 注入：把图谱检索到的语义路径注入 AnalysisAgent Prompt。
6. 风险解释：通过路径说明为什么某个事项需要确认。

示例推理链：

- 输入：“下午血压有点高，明天上午9点复查。”
- 图谱路径：“血压偏高 -> 需要具体数值 -> 复诊沟通材料 -> 明天9点复诊”。
- 输出任务：“补充下午血压具体数值和测量时间；把最近三天血压记录放入复诊材料。”

再如：

- 输入：“晚上还没确认有没有吃药。”
- 图谱路径：“药物事件 -> 状态不确定 -> 重复服药风险 -> 需要现负责监护人确认”。
- 输出安全提醒：“未确认前不要自行重复服药，药物相关按医嘱执行。”

知识图谱的技术价值：

- 为模型提供拓充辅助语义信息，降低纯文本推理遗漏。
- 支持多跳风险解释，让提醒更可解释。
- 支持跨天、跨对象、跨监护人的长期照护追踪。
- 与个人知识库结合，实现对象级个性化推理。

## 8. 个人知识库与知识图谱协同

个人知识库负责保存用户级、对象级记忆；知识图谱负责表达照护实体和关系。二者协同后，可以形成更强的个性化推理能力。

当前知识库实现：

- SQLite 存储记忆文本、标签、向量、用户 ID、监护对象和时间戳。
- Embedding 模型生成记忆向量。
- Numpy 余弦相似度检索相关记忆。
- 每个监护对象拥有独立知识库，宝宝、老人、宠物互不干扰。

协同示例：

- 知识库记住“爷爷复诊前要准备医保卡和病历本”。
- 知识图谱识别“明天上午9点医院复查”。
- Pipeline 结合二者生成“今晚把医保卡、病历本、最近三天血压记录放入包里”。

## 9. 前端交互与可视化实现

前端不是普通聊天框，而是家庭照护指挥台：

- 左侧侧边栏：今日监护、监护人、历史信息、知识库、视频聊天。
- 今日监护首屏：上方两栏分别放输入区和核心交接卡。
- 下方详情区：信息图、风险雷达、已完成事项，需要向下滚动查看。

- 视频观察：使用浏览器摄像头/麦克风做远程观察入口。

## 10. 安全边界与合规设计

CareRelay AI 只做家庭照护信息整理和提醒，不做医疗诊断，不提供自行调整药物剂量建议。

安全机制包括：

- Prompt 层限制：明确禁止诊断和剂量建议。
- SafetyAgent 后处理：涉及药物、处方、症状时强制加入“按医嘱执行/联系医生确认”。
- 不确定项隔离：所有不确定信息进入 to_confirm，而不是直接当作已完成。
- 高风险事项优先级：药物、异常、复诊等任务自动提升优先级。
- 家属沟通表达：语气温和、明确、可执行，减少焦虑和误解。

## 13. 总结

CareRelay AI 当前版本已经完成从三模态输入到结构化交接输出的完整技术闭环。系统不仅实现了可运行的前后端 Demo，还搭建了多 Agent Pipeline、个人知识库、模型后训练链路和家庭照护知识图谱。模型后训练提升垂直领域专项能力，知识图谱为模型推理拓充辅助语义信息，两者共同增强了交接卡的准确性、可解释性、个性化和安全性。

这使 CareRelay AI 不再只是一个聊天式工具，而是一个面向真实家庭照护协作的智能交接系统原型。
